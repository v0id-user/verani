## 0. Context

Project name: **Verani**

Goal:
A small, focused realtime SDK that feels like "Socket.io for Cloudflare Durable Objects / Actors":

* Per-connection architecture (one DO per user)
* WebSockets under the hood
* Cloudflare **Actors** abstraction as the backend runtime
* Handles **hibernation** correctly
* Room coordination via separate RoomDOs and RPC
* Horizontally scalable by design

This is a **library**, not an app.

---

## 1. High level architecture

Core idea:

* Each **ConnectionDO** instance owns ONE WebSocket connection for a single user
* **RoomDOs** coordinate room membership and message fanout via RPC
* No single-threaded bottleneck - each user has their own DO
* Idle connections hibernate and cost nothing

The SDK has two halves:

1. **Backend**

   * `defineConnection` - define a per-user connection handler
   * `createConnectionHandler(definition)` - create a ConnectionDO class
   * `createRoomHandler(definition)` - create a RoomDO class for coordination

2. **Client**

   * `VeraniClient`
   * Simple `on(event, handler)` / `emit(event, payload)` API over WebSocket

Protocol: JSON frames, very simple:

```ts
type MessageFrame = {
  type: string
  channel?: string
  data?: any
}
```

---

## 2. State model and hibernation

Key constraint: Durable Objects / Actors **hibernate** when idle. That means:

* Any **in memory** state is wiped when the process is evicted
* Existing WebSockets are still logically attached and can wake the Actor again via new messages
* When the Actor wakes, we must rebuild our in memory state from the WebSocket and its attachment

ConnectionDOs handle hibernation by:

1. Storing metadata as WebSocket attachments (`ws.serializeAttachment(meta)`)
2. Persisting room membership to DO storage
3. Re-joining RoomDOs on wake to ensure they know the user is still connected

---

## 3. Architecture topology

### ConnectionDO (One Per User)

* **Identity:** `ConnectionDO.get(userId)`
* **Owns:** Single WebSocket connection (hibernatable), minimal session metadata, room membership (persisted)
* **RPC Methods:** `deliverMessage(event, data)`, `joinRoom(roomName)`, `leaveRoom(roomName)`

### RoomDO (One Per Room/Channel)

* **Identity:** `RoomDO.get(roomName)`
* **Owns:** Member list (Set of userIds), shared room state, no WebSocket connections
* **RPC Methods:** `join(userId)`, `leave(userId)`, `broadcast(event, data)`

## 4. Public API design

From a user's perspective on the backend:

```ts
import { defineConnection, createConnectionHandler, createRoomHandler } from "verani";

const userConnection = defineConnection({
  extractMeta(req) {
    const url = new URL(req.url);
    return {
      userId: url.searchParams.get("userId") || crypto.randomUUID(),
      clientId: crypto.randomUUID(),
      channels: ["default"]
    };
  },

  async onConnect(ctx) {
    await ctx.actor.joinRoom("chat");
  },

  async onDisconnect(ctx) {
    // Room leave is handled automatically
  }
});

userConnection.on("chat.message", async (ctx, data) => {
  await ctx.emit.toRoom("chat").emit("chat.message", {
    from: ctx.meta.userId,
    text: data.text
  });
});

export const UserConnection = createConnectionHandler(userConnection);
export const ChatRoom = createRoomHandler({ name: "ChatRoom" });
```

Client side:

```ts
import { VeraniClient } from "verani/client";

const client = new VeraniClient("wss://example.com/ws?userId=123");

client.on("chat.message", (data) => {
  console.log("Message:", data);
});

client.emit("chat.message", { text: "hello" });
```

  actor/
    connection-actor.ts  # Per-user ConnectionDO
